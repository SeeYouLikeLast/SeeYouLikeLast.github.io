对数器

假设你写了一个很快的算法，但你不确定它对不对。
这时候可以再写一个：

  • 绝对容易想到
  • 虽然慢，但基本不会错
  • 逻辑很直接
    的“笨方法”，然后让这两个方法在大量随机数据上反复比较结果。
    如果两者结果永远一样，就说明你的快算法大概率是正确的。
    这就叫 对数法 / 对数器。

对数法本质上是：
用一个可靠但可能很慢的方法，去验证一个高效但不容易证明正确的方法。

  1. 设计一个随机样本生成器
  2. 写一个暴力方法
  3. 写一个高效方法
  4. 大量测试并比较结果
  5. 一旦发现两者结果不同，把那组输入拿出来单独分析。

隐藏 bug 可能很多，比如：

  • 边界越界
  • 空数组处理错误
  • 重复值处理错误
  • 二分条件写错
  • 排序稳定性出问题
  • 递归出口错了

排完序之后, 原本相等的数的位序没有发生变化
(可以多类别排序后, 可以多轮筛选
eg: 先排年龄小的,在排班级小的,这样就是按照班级小的并且年龄小的 )

快排 最快(时间上) —— 一般默认快排
要求空间复杂度—–堆
要求快 并且 时间复杂度—– 归并

异或^

异或定义

  1. 相同为 0，不同为 1。
  2. 异或是二进制下的不进位加法。

基本定律

  1. a ^ 0 = a
  2. a ^ a = 0
  3. a ^ b = b ^ a
  4. (a ^ b) ^ c = a ^ (b ^ c)
  5. a ^ b ^ a = b
  6. 一个数出现偶数次会抵消，出现奇数次会保留。

高频易错点

  1. 值相同不等于同一个变量。
  2. 数组异或交换必须保证 i != j。
  3. 异或不是普通加法。
  4. 前缀异或题常要加空前缀 0。

排序

排序总结

快排 最快(时间上) —— 一般默认快排
要求空间复杂度—–堆
要求快 并且 时间复杂度—– 归并

堆排序

  1. 时间复杂度稳定为 O(N log N)
  2. 空间复杂度 O(1)
  3. 不稳定

归并排序

  1. 时间复杂度稳定为 O(N log N)
  2. 空间复杂度 O(N)
  3. 稳定

快速排序

  1. 平均 O(N log N)
  2. 最坏 O(N^2)
  3. 一般空间复杂度较低
  4. 不稳定
  • 基于比较的排序算法，不可能突破 N log N 这个级别的下界。
  • 既要时间复杂度稳定为 O(N log N), 空间复杂度 O(1) , 稳定的算法不存在
排序算法 最好时间复杂度 平均时间复杂度 最坏时间复杂度 空间复杂度 稳定性
冒泡排序 O(N) O(N^2) O(N^2) O(1) 稳定
选择排序 O(N^2) O(N^2) O(N^2) O(1) 不稳定
插入排序 O(N) O(N^2) O(N^2) O(1) 稳定
二分插入排序 O(N^2) O(N^2) O(N^2) O(1) 一般可写稳定
归并排序 O(N log N) O(N log N) O(N log N) O(N) 稳定
快速排序 O(N log N) O(N log N) O(N^2) O(log N)~`O(N)` 不稳定
随机快排（荷兰国旗） O(N log N) O(N log N) O(N^2) O(log N)~`O(N)` 不稳定
堆排序 O(N log N) O(N log N) O(N log N) O(1) 不稳定
计数排序 O(N + K) O(N + K) O(N + K) O(K) 可稳定
基数排序 O(d(N + K)) O(d(N + K)) O(d(N + K)) O(N + K) 稳定
桶排序 近似 O(N) 与分布有关 最坏可退化 与桶数量有关 视实现而定
  1. 冒泡排序 不断比较相邻两个数，把大的往后推。
  2. 选择排序 每次从剩下的数里，挑一个最小的放到前面。
  3. 插入排序 前面始终保持有序，每次把新来的数插到正确位置。
  4. 希尔排序 插入排序的升级版，先隔着排，再慢慢缩小间隔。
  5. 归并排序 把数组一分为二，再把每一半继续分，直到每组只剩一个数。因为一个数天然有序，然后再两两合并成有序数组， 最后整个数组就有序了。
  6. 快速排序 随机找一个“标准数”，把小的放左边，大的放右边
  7. 堆排序 先把数组调整成“大根堆”或“小根堆”，再不断取最大或最小。
  8. 计数排序 不比较大小，而是统计每个数出现了几次。
  9. 桶排序 先把数字按范围分到不同桶里，再对每个桶内部排序。
  10. 基数排序 按个位、十位、百位……一位一位地排。

递归

递归，就是：一个方法在它的内部再次调用它自己。

也可以理解成：把一个大问题, 拆成若干个和原问题“同类型”的小问题, 先解决小问题, 再利用小问题的结果解决大问题

基本结构

压栈阶段
一层一层调用自己，把现场保存到栈中。
出栈阶段
当到达递归出口后，开始一层一层返回，把结果向上交还。

其中：

  • a：每次递归分成几个子问题

情况 1：log_b(a) > d
那么：
T(N) = O(N^(log_b(a)))
说明：
递归子问题的总工作量更大，主导整体复杂度。

情况 2：log_b(a) < d
那么：
T(N) = O(N^d)
说明：
每层额外工作的复杂度更大，主导整体复杂度。

情况 3：log_b(a) == d
那么：
T(N) = O(N^d * logN)
说明：
递归部分和每层工作量势均力敌，所以会多出一个 logN。

归并排序

归并排序是一种典型的分治算法。
它的思想是：

  1. 把数组从中间分成左右两半
  2. 左边排好序
  3. 右边排好序
  4. 再把两个有序部分合并起来
    核心就是两个字： 分 + 合

1.小和问题

小和问题定义：对于数组中的每个数，求它左边比它小的数的和，最后把所有位置的结果加起来。

原定义是： 每个数看左边有多少个比它小的数
换个角度看也可以变成：每个数看右边有多少个比它大的数，它就会被累计多少次

在归并时：

  • 左组有序

  • 右组有序

  • 只有严格小于时，左边元素才产生小和

  • 如果相等，必须先拷右组

2. 逆序对

前面的数比后面的数大，这样的一对数就叫逆序对。

时间复杂度: O(N log N)

空间复杂度: O(N)
因为 merge 过程要用辅助数组。

快排

快速排序（Quick Sort）的核心思想是：

  1. 选一个数作为划分值（pivot）
  2. 把数组分成几部分
  3. 左边比它小
  4. 中间等于它
  5. 右边比它大
  6. 再递归处理左右两边
    它也是典型的分治算法。

1.荷兰国旗问题

问题本质是：

给定一个数 num，把数组划分成三部分：

  • 左边都小于 num
  • 中间都等于 num
  • 右边都大于 num
    这就叫三路划分。

完全二叉树

数组存储

完全二叉树指的是：

除了最后一层，其余每一层的节点数都达到最大；
最后一层的节点都连续地集中在左边。

也就是说：

  1. 上面的层必须全满
  2. 最后一层可以不满
  3. 最后一层缺失的位置只能出现在右边，不能左边空了右边还有节点

完全二叉树最重要的性质是：可以直接用数组存储，不需要真的建链式节点结构。

如果数组下标从 0 开始，那么对于任意下标 i：

  • 父节点下标：(i - 1) / 2
  • 左孩子下标：2 * i + 1
  • 右孩子下标：2 * i + 2

为什么堆一定基于完全二叉树
因为堆要求：

  1. 能快速找到父节点
  2. 能快速找到左右孩子
  3. 能紧凑存储，不浪费空间
    完全二叉树正好满足这些要求。
    如果不是完全二叉树，就无法直接按数组下标规律找到父子关系。

堆

数组存储
堆是一种特殊的完全二叉树。
堆分两种：

  1. 大根堆
  2. 小根堆
    堆在结构上满足： 必须是完全二叉树

堆在值上还满足：

  • 大根堆：每棵子树的根都最大
  • 小根堆：每棵子树的根都最小
大根堆特点
  1. 堆顶元素最大
  2. 适合快速取最大值
  3. 常用于：
    • 堆排序
    • 求数组前 K 大
    • 优先级队列
小根堆特点
  1. 堆顶元素最小
  2. 适合快速取最小值
  3. 常用于：
    • 优先级队列
    • TopK 问题
    • 合并有序数据
    • Dijkstra / Huffman 等

堆插入（heapInsert） 自下向上

当一个新元素加入堆尾之后，可能会破坏堆结构。所以要做一个调整过程，让它重新满足堆的性质。这一步叫： 堆插入

大根堆
假设新元素放在数组最后一个位置。如果它比父节点大，那么就交换，继续往上看。
一直到：

  1. 到达根节点。
  2. 它不再比父节点大。

堆化（heapify）自上向下

heapify 指的是：某个位置的值变小了（大根堆）或者堆顶被替换后， 把这个节点向下调整，重新恢复堆结构。
也叫：向下调整/下沉

大根堆 heapify 思想
对于当前节点：

  1. 找左右孩子中较大的那个
  2. 如果孩子比当前节点大，则交换
  3. 当前节点继续往下沉
  4. 直到不需要交换为止

适合场景：

  • 堆顶元素被替换
  • 删除堆顶
  • 堆排序时交换堆顶与末尾后恢复堆

堆排序

堆排序通常基于大根堆实现升序排序。(小根堆—降序(放到数组末尾无需新建空间))

步骤如下：

  1. 先把数组建成大根堆
  2. 此时堆顶是最大值
  3. 把堆顶和堆最后一个元素交换
  4. 堆大小减 1
  5. 对新堆顶做 heapify
  6. 重复上述过程
    这样每轮都把一个最大值放到数组最后。
    最终数组从小到大有序。

题型 1：数组中的第 K 大元素

题意

在一个无序数组中，找第 K 大的元素。

方法一：大根堆

把所有元素建成大根堆，然后弹出 K-1 次，第 K 次弹出的就是答案。

时间复杂度：

O(N + K log N)

方法二：小根堆（更常用）

维护一个大小为 K 的小根堆：

  1. 前 K 个元素先入堆
  2. 后面每来一个元素：
    • 如果比堆顶大，就替换堆顶并 heapify
  3. 最后堆顶就是第 K 大

时间复杂度：

O(N log K)

题型 2：Top K 问题

题意

找数组中最大的前 K 个数。

思路

维护大小为 K 的小根堆。

因为：

  • 堆顶始终是这 K 个数中最小的
  • 新来的数如果比堆顶还小，就没资格进入前 K
  • 如果比堆顶大，就替换进去

题型 3：数据流中的中位数

思路

用两个堆：

  1. 大根堆：保存较小的一半
  2. 小根堆：保存较大的一半

并且保证：

  • 两个堆大小差不超过 1
  • 大根堆堆顶 <= 小根堆堆顶

这样就能快速取中位数。

题型 4：合并 K 个有序链表 / 有序数组

思路

用小根堆维护当前每个链表（或数组）的最小候选值。

每次弹出最小值，然后把它后面的元素加入堆。

这是典型的小根堆应用。

题型 5：几乎有序数组排序

题意

一个数组中，每个元素移动距离不超过 K，对它排序。

思路

使用小根堆。

因为每个元素最终位置离当前位置不远，所以：

  1. 先把前 K+1 个元素放入小根堆
  2. 每次弹出堆顶放到答案位置
  3. 再加入后一个元素

时间复杂度：

O(N log K)

贪心算法 / 优先队列 + 哈夫曼合并  O(n log n)
题目要求以最小总代价将多根木棍合并成一根，每次合并代价为两根木棍长度之和。

使用最小堆（优先队列） 实现贪心策略：

  1. 将所有木棍长度放入最小堆。
  2. 重复取出两根最短木棍合并，并将新木棍长度重新放入堆中。
  3. 将每次合并的代价累加即为最小总成本。
    这种策略能保证局部最优叠加为全局最优，类似于哈夫曼编码生成树时的最优合并原则。
